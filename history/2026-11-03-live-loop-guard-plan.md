## Design and acceptance

Use the existing LoopStep/action-bound event capture and audit, with exact semantic
action arguments, observed outcomes and host state versions. A pending decision
must bind its existing PredictionCommit and ActionRecord. Fresh host context
authentication verifies source provenance, current state and any claimed human
recheck/independent-verification/productive-repeat exception. Uncertainty routes
to review, not a deterministic moral violation or fabricated completion.

Only a prior verified structural repeat can trigger independent loop review.
Require the latest matching action and no intervening novel/informative action;
new observations or changed state permit ordinary processing. The reviewer uses
the existing RelationalVerificationResult, binding both previous/repeated source
observations to repeated_failed_route. A verified unproductive repeat is blocked
without consuming an execution authorization. Useful rechecks remain eligible.

The synchronous execution adapter recomputes the guard rather than trusting
exported JSON. Every eligible execution still consumes the existing exact one-use
runtime authorization against the host registry/clock before invoking the host
executor. A loop decision never grants action authority. Blocking or escalation
does not terminate the task or certify a replacement answer; the host retains
evidence and selects an authorized continuation through existing PEO procedures.

Everything is opt-in and versioned. Disabled guard inspection touches no history;
the execution adapter still enforces existing authorization. Bound input/output
before callbacks, retain source/decision provenance and suppress private callback
exception text. No canonical cases, verifiers, grants or governance rules change.

CPU-safe tests must exercise actual callback suppression and one-use authorized
delegation, human rechecks, independent verification, changed state/new outcomes,
